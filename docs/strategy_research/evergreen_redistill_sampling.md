# Evergreen 重新蒸餾:樣本與計劃定案(2026-08-05 覆核版)

**使用者指示**:「你先決定好重新蒸餾用的樣本」→「再讓我 Review 一次,確認資料以及
計劃都正確了嗎?」

## 一句話結論

**正例 216 檔 + 配對負例 216 檔,期間 2008-01 ~ 2021-12,與標記/回測期(2022-07 起)
完全不重疊。** 舊 224 檔不丟棄,其中 126 檔(70 正 + 56 負)在乾淨資料上仍成立,
連同 100% 已在庫的消息材料**降級為驗證集**。

- 清單:`var/out/evergreen_ev57_positives.csv` / `..._negatives.csv`
- 產生器:`src/quantlib/evergreen/ev57_station_sample.py`(seed 20260727,可重跑)
- 重驗器:`src/quantlib/evergreen/ev56_sample_recheck.py`(舊樣本在乾淨資料上的存活率)
- 提示詞草案:`src/quantlib/evergreen/draft/PROMPT_ev58_*.md`

## 為什麼重選——五個問題,逐一有數字

| # | 問題 | 證據 | 狀態 |
|---|---|---|---|
| 1 | **資料汙染** | 舊 168 檔在乾淨資料上只剩 **42%** 成立(35% 漲幅不到門檻、23% 是公司行動的機械跳動) | 已換樣本 |
| 2 | **選樣方法** | 用原始收盤價、把含公司行動的窗整段丟棄(丟掉 13.7% 的合格窗,丟的是高配息配股整類公司);水平線 60 交易日與標記任務問的「2-6 個月」不一致 | 改還原價 + 120 交易日 |
| 3 | **蒸餾期 = 標記期** | 樣本 2022-07~2025-06、標記月份 2022-07~2025-04、refit 窗 2023-07~2026-07 全部重疊;哲學逐條引用具名個股(常珵/大綜/富野/8404…)與「關稅崩盤底部反彈」(2025-04) | 蒸餾期整段前移 |
| 4 | **t0 錨定在漲勢起點** | 標記者站在月度站位日,不可能知道今天就是起漲日。實測:起點日錨定的正例 prior120 中位 **−7.3%**(系統性挑在低點)、站位日錨定 **+3.7%** | 改站位錨定 |
| 5 | **對照組入選條件不對稱** | 舊對照要求「前 120 日漲 ≥25%」而正例無此條件 → 兩組動能差 **41 個百分點**,蒸餾必把混淆因子學成判別 | 改配對動能十分位 |

**第 3 點為什麼最嚴重**:標記 Agent 被要求 PIT,但**它的判斷框架本身已經知道那些
月份的答案**。PIT 管得住搜尋,管不住框架裡的後見之明——這讓 2022-2026 的回測在
方法上不成立,無論資料多乾淨。

## 資料前提:一個必須先修的空洞(2026-08-05 已修)

EV55 順手挖到、但一直沒人接手:`ex_right_dividend/twse` **2023-09 ~ 2024-06 十個月
零筆**,raw 封存也無檔案。實測 MOPS 端點對那幾個月都回得出資料——不是端點不給,
是爬蟲從沒跑過。

**根因是通病**:月頻源的 `refresh()` 只重抓最近 `_REFRESH_MONTHS = 3` 個月;停超過
3 個月的月份**永遠不再被看一眼,且無任何機制會發現**。ex_right_dividend 是還原價
因子的原料,缺一個月 → 該月還原價機械跳空 → 所有以還原價為輸入者失真,而症狀與
真實行情難以分辨。該窗正落在 live refit 窗內。

已修:`src/quantlib/crawl/monthly_coverage.py`(覆蓋稽核 + 補洞)。補回 41 個有事件
月份,稽核由「4 源共 44 個疑似空洞」收斂為 **✓ 全部逐月連續**。另加「無事件也留
0-byte sentinel」,讓「問過了沒東西」與「從沒問過」不再無從分辨。

**後果須知**:資料世代改變後 Evergreen CAGR 由 live_config 記錄的 2.8703 變成
2.8830(+1.27pp),`test_engine_parity` 紅燈——**守衛正確動作**。依專案鐵律不擅自
重錄 live_config,留使用者裁決。

## 設計決定逐條(每個數字寫得出出處)

| 決定 | 值 | 理由 |
|---|---|---|
| 價格基準 | `prices.fetch_adjusted_panel` 還原價 | 專案鐵律:報酬計算一律走 canonical prices。能穿過除權息/減資,不必丟樣本 |
| t0 錨定 | **月度站位日**(當月 10 日後首個交易日) | 與 live 標記日曆完全相同。起點日錨定會系統性挑在低點(見問題 4) |
| 水平線 | 站位次日起 **1~120 交易日**的還原總報酬**區間最高值** | 對齊標記任務的「未來 2-6 個月」。不排除前兩個月——排除會把「即點即燃」整類系統性剔除 |
| 門檻 | ≥ **80%** | 沿用「大幅上漲」語義以與舊工作可比。敏感度已量:≥50% → 14.21%、≥80% → 6.38%、≥100% → 4.08% |
| 蒸餾期 | t0 ∈ [2008-01, 2021-12],前瞻窗須在 2022-07-01 前結束 | 與標記/回測期零重疊。起點 2008 因 tpex 資料 2007-07 才開始 |
| 標的 | 四碼普通股 + t0 當下已申報月營收 | 自查抓到舊抽樣混入 00633L/00655L(槓桿 ETF)、020010(ETN)、**70391/71540(權證)**、912398(TDR)——對這些做消息面歸因無意義 |
| 流動性 | 當日**橫斷面 ADV20 十分位**,只標記不過濾 | 絕對金額在 2008 與 2021 意義不同。EV55 量到最低十分位命中 11.3%、其餘九分位 5.5-7.0% 平坦——**只有 1.8 倍富集,84% 的暴漲在最低十分位之外**,故「暴漲集中在小型股」不足以作為過濾理由,留作維度才對 |
| 分層 | **regime × 流動性層**,格內依年輪抽 | EV55 量到蒸餾期崩跌只有 23 個站位,而各 regime 基準率差異大(崩跌 17.6% / 修正 6.4% / 多頭 5.9% / 狂熱 7.5%);按年分層會稀釋最稀缺且最有資訊量的崩跌樣本,而哲學第十道判別正是「宏觀 regime 時點」。輪抽避免崩跌那格全擠在 2008 單一事件 |
| 負例 | 同站位 × 同流動性十分位 × 同**動能十分位** × 同產業(逐級放寬),分 `near_miss`(25~50%)與 `quiet`(<15%)兩檔硬度 | 動能進配對鍵是問題 5 的正解。兩檔硬度:只有 near_miss 學不到「與沉寂股的差別」,只有 quiet 則對比太容易 |
| 年代標籤 | `limit_era` = 7% / 10% | 台股漲跌幅 2015-06-01 由 7% 放寬到 10%,是市場微結構斷點。標記期全在 10% era,故 7% 樣本屬外推,可分開檢視或整層剔除而不必重抽 |

## 樣本輪廓(2026-08-05 於修正後資料重抽)

- **正例 216**(regime × 流動性層各 18,四個 regime 完全均衡)
- **負例 216**(near_miss 108 / quiet 108);配對品質 L1 65 / L2 128 / L3 23
  → **89% 落在同站位 + 同流動性十分位 + 同動能十分位**
- 年份涵蓋 2008-2021 全部 14 年(每年 6~29 檔,輪抽生效)
- **一檔股票只出現一次**:432 個樣本 = 432 個不重複代碼,正負零交集(見下節)
- **混淆因子已消**:正例 prior120 中位 +4.4% vs 負例 +2.1%(**差 2.3pp**,原為 41pp);
  動能十分位分布兩臂近乎重合(正 33/23/15/14/11/12/15/26/26/41、
  負 30/24/17/14/11/13/14/25/31/37)
- 母體基準率 **6.38%**(180 個月度站位、244,608 個「檔 × 站位」)——盲判的機率校準錨

## 舊樣本降級為驗證集

| 舊資產 | 乾淨資料重驗 | 新角色 |
|---|---|---|
| 168 正例 | 70 檔仍成立(42%) | 驗證集(2022-2025,對新哲學為 OOS) |
| 56 負例 | **56 檔全數仍成立(100%)** | 驗證集 |
| ev27_news 材料 224 檔 | 外部新聞,與價格資料無關 → 完全乾淨 | 驗證用,零額外搜尋成本 |

負例 100% 存活的原因:汙染機制是「製造假暴漲」,只會把偽形變成非偽形,不會反向。

**驗證方式**:哲學蒸餾完成後,把這 126 檔**僅 `pit == "pre_t0"`** 的材料餵給標記
Agent 盲判「會暴漲 vs 偽形」,量準確率。這是舊哲學**從來沒做過**的 held-out 測試。
紀律:驗證集只能用一次;若據以調整哲學,它就變成訓練集。

**這條路徑已實測可行(2026-08-05)**:`ev27_news` 的 224 個樣本檔全部帶 `pit` 欄位,
1,088 筆材料中 701 筆是 `pre_t0`,**224/224 個樣本都至少有一筆**,零檔落空。
但要先講清楚它的**檢力上限**:每個樣本的 `pre_t0` 材料中位數只有 **3 筆**(分布
1:2 檔、2:57、3:92、4:60、5+:13),只有一筆的有 2 檔。三筆材料撐起的盲判,單檔
判斷本來就雜訊很大;它能回答的是「整體準確率明顯高於 6.38% 基準率嗎」,**回答不了
「哪一條規則有效」**。把它當成規則層級的證據,是拿 126 個樣本去測十幾條規則。

## 一檔股票只出現一次(2026-08-05 第八輪補的硬約束)

原本沒有這條,實測 432 檔裡 **60 檔重複、最多 4 次,32 檔同時當過正例與負例**,
其中 9 檔的兩個站位相隔不到半年。三個後果各自都足以致命:

1. **PIT 破功**——歸因 agent 研究同一檔的兩個站位時,做晚站位查到的材料會留在上下文
   裡;若批次順序讓晚站位先做,早站位那張卡就是帶著未來資訊寫的,而卡片看不出異樣。
2. **臂別露餡**——同一家公司出現兩次(一次正一次負),agent 幾乎必然認出來,而身分卡
   還是跨檔共用的,認出的成本近乎零。
3. **有效樣本數灌水**——同一家公司的兩個時點不是兩個獨立觀測,所有下游信賴區間都
   建立在「432 個獨立樣本」之上。

已改為硬約束(正例貪婪取、負例配對時吃同一個已用代碼集合)。正例母體 15,598,深度
遠夠填滿配額,**分層完全不受影響**(每格仍 18 檔)。

## 已知性質:樣本偏向 7% 漲跌幅世代(2026-08-05 量測)

各期別樣本數(正負合計 432):

| 期別 | 期間 | 世代 | 樣本 |
|---|---|---|---|
| E1 | 2008-01~2010-12 | 7% | 128 |
| E4 | 2011-01~2013-12 | 7% | 112 |
| E3 | 2014-01~2015-05 | 7% | 40 |
| E6 | 2015-06~2017-12 | 10% | 42 |
| E2 | 2018-01~2019-12 | 10% | 46 |
| E5 | 2020-01~2021-12 | 10% | 64 |

**7% 世代 280 檔(65%)、10% 世代 152 檔(35%)。** 成因:崩跌 regime 只存在於
2008-2011,而分層是 regime × 流動性層各 18 檔,崩跌那三格(54 檔正例)全部落在
7% 世代。這是「保留 7% 那半以換取崩跌覆蓋」的必然代價,不是抽樣錯誤。

**這件事怎麼被檢驗**:期別保留組 = **每個漲跌幅世代各自最近的那個期別**
(2014-01~2015-05 + 2020-01~2021-12,合計 104 檔 ≈ 24% 樣本;由
`ev58_prompt.era_split()` 依日期規則算出,不由人挑)。若哲學在 10% 世代的保留期別上
大量 `holdout_failed`,就是「它學到的是 7% 世代特有的東西」的直接證據,而那會在燒完
標記成本之前就出現。

選「最近」而非「最大」有兩個理由:(a) 最近的期別離下游標記期(2022-07 起)最近,
在它身上能複製才是最強的移植證據;(b) 取最大的 7% 期別(E1,128 檔)會把 2008-2010
整段拿去當保留組,而**崩跌 regime 的樣本全在那裡**——蒸餾從此看不到崩跌,而哲學
第十道判別正是宏觀 regime 時點。保留組的檢力不值得用「蒸餾看不到最稀缺的樣本」去換。

**選法刻意不寫進蒸餾提示詞**:期別碼是密封的(打亂、不依時序),而「保留組是每個
世代最近的那個」等於直接告訴蒸餾器兩個保留期別在時間軸上的位置——認出年代,對台股
那幾年的記憶就會灌進判斷,正是這次重做要根除的東西。提示詞只寫「切分由編排決定、
不准反推年代」。

## 密封強度的實測邊界(已知殘留,不假裝完美)

蒸餾器看到的是機制卡,而機制卡的去識別鐵律 (e) 已明文禁止寫出 `limit_era`
(「7%」等於直說站位在 2015-06 之前,年份禁令蓋不到它)。因此蒸餾器**無法**把期別碼
分成 7%/10% 兩群,期別打亂的密封在它那一側是完整的。

歸因 agent 則相反:它必須看到 `limit_era` 才判得出「這是市場制度的產物」,也必須知道
自己站在哪一年才做得了 PIT 檢索。它的隔離靠的是另一套機制——真相釋出閘門(見下)
與逐案黑名單正則掃描,而不是密封。**兩個角色的隔離手段不同,不要混為一談。**

## 真相釋出是閘門,不是紀律(2026-08-05 第六輪修)

原本真相檔與樣本卡同目錄,而歸因提示詞從第一秒就帶著那個路徑——「物理隔離」實際上
退化成「請你不要看」。現在真相寫在另一個根(`var/out/ev58_truth/`,從不交給 agent),
由 `ev58_prompt.release()` 逐檔驗明該批階段 A 的 `ex_ante_d_prev.json` 與
`ex_ante_d0.json` 都已落地,才複製進 agent 看得到的位置;缺任一檔即整批拒絕,並比對
mtime 確認真相檔晚於所有階段 A 落檔。理由是不對稱:早釋出一次,該批盲判永久失效且
事後從卡片與報告完全看不出來;晚釋出只是多跑一次指令。

## 未解(需實測,不可臆測)

**老年代的消息可得性。** 粗探針(WebSearch 三關鍵字)對 2008 / 2016 / **2020** 的
樣本都只回傳常青個股資訊頁。但該探針不足以下結論——舊那批 2022-2025 的歸因能成功
靠的是多輪針對性查詢 + WebFetch + Wayback + Chrome。MOPS open API 實測僅含近期公告。

**處理方式**:不預先砍掉任何年代。樣本已打 `limit_era` 與 `regime` 標籤,**先按年代
分批小規模試跑**,實測「查無 t0 前消息」比率再決定是否剔除某層。及格線寫在
`PROMPT_ev58_*` 裡(該批 6 檔中至少 4 檔 `retrievability_score ≥ 2`)。

## 這樣做之後,回測才重新有效

蒸餾期 2008-2021 → 哲學 → 標記 2022-07 起 → 回測 2022-07 起。
哲學對回測期而言是**完全樣本外**,2022-2026 的回測數字才第一次具備方法上的效力。

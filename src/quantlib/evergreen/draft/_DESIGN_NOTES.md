# EV51 重新蒸餾提示詞草案 — 設計要點與未解風險

> 由五路獨立設計(第一性原理 / 防後見之明 / 下游倒推 / 舊年代可執行性 / 選樣交叉檢查)
> 收斂而成。**其中的量化宣稱我已逐條自行驗證**,結果見 `_VERIFICATION.md`。

## 總體切入角度

把歸因從「解釋已知結果」改造成「站在標記日的盲測下注 + 逐格留痕的檔案考掘」——並讓蒸餾器物理上只讀得到去識別化的機制卡與程式算好的統計表,使三個問題各自被一個機制(而不是一句紀律)擋住。

## 關鍵改動

1. 【問題 3・時期重疊 / meta 層 look-ahead → 雙軌輸出 + 資訊隔離】每檔階段 B 產出兩份:`case_record`(具名、含精確日期,永久存檔供審計)與 `mechanism_card`(去識別:假名 S037/C112、密封期別碼 E1..E6、相對交易日 offset,零公司名零年份)。**蒸餾器只讀得到 mechanism_card 與程式算好的統計表**。這是我在五個設計的正面衝突上明確選邊:設計 3、5 只禁哲學「輸出」具名(靠自律),設計 2 禁「輸入」具名(靠隔離);我選隔離,因為現行 PHILOSOPHY.md 的十道判別條條掛著常珵、系微、聯詠——那正是自律版本的實測結果。同時保留設計 4 的具名 case_record,避免設計 2「哲學不可回溯查證」的缺陷。再加機械守護:regex 掃四碼代碼 + `(19|20)\d{2}` + 樣本公司名黑名單,**發射前必須先用現行 PHILOSOPHY.md 跑一次確認會紅**(先紅後綠)。

2. 【問題 2・水平線不一致 → 站位錨定 + 兩站位】t0 從「暴漲起點日」(事後才知道、標記 Agent 永遠拿不到的視角)改為**月度標記站位日**(當月 10 日後首個交易日),與 live 完全同一套日曆。結果視窗改為自站位次一交易日起 **1..120 交易日的還原總報酬區間最高值**。這裡我對設計 1、3 的「40-120 交易日」明確選相反邊:排除前兩個月會把「即點即燃」那一整類催化系統性剔除,而現行哲學正宣稱那類存在——那會讓蒸餾偏向慢速機制。附帶效果:現行哲學「決定性硬消息絕大多數落在 t0 之後 1-3 個月」極可能只是事件錨定挑到完美起漲日的產物,站位錨定後這條第一次能被當規律檢驗。

3. 【每檔給兩個站位 d_prev 與 d0,各做一次獨立盲判、各自獨立計算結果標籤】設計 3 要三站、設計 5 要一站,我選兩站:兩站以一輪搜尋切片取得(邊際成本低),就能量到現行框架完全答不出的兩件事——「早一個月看得出來嗎」(可標記窗口的寬度)與「等一個月的資訊價值」(d0 的 AUC 減 d_prev 的 AUC)。三站則會讓 agent 從結構猜出中間那站是關鍵,且輸出量翻倍。

4. 【問題 1・資料汙染 → 抽樣層走還原價 + 歸因層當第二道守門】樣本一律以 `prices.fetch_adjusted_panel` 還原價量測,含除權息/減資的窗不再整段丟棄(舊法丟掉的不是隨機一批,是高配息高配股那一整類公司)。同時要求 agent 若從 MOPS 公告發現漲跌其實對應減資換股、面額變更、合併換股、分割、借殼、長停復牌補價,必須回報 `sample_flag=mechanical_suspect` 讓上游剔除。質化工作(核對公告)做量化守門,不違反分工。

5. 【盲判先行:歸因的核心從『敘事』換成『可計分的下注』】階段 A 全程不知結果(批次混編、比例不揭露、兩組樣本卡欄位完全相同),必須輸出 `p_up80`(0-100)、`mark_or_not`、`conviction`、`strongest_disconfirmer`、`kill_criteria` 三條,寫入 `ex_ante/` 凍結後才准進階段 B。這一刀同時解掉三件事:(a) 判別理由是在不知道答案時寫下的,不是事後合理化;(b) 盲判 AUC 本身就是頭條數字——若貼近母體基準率,整條質化路線當場被證偽,省下後面所有錢;(c) 誤判覆盤會逼出 `unknowable`(當天真的無從得知)這個誠實邊界。校準用的母體基準率**我實測給定 6.3%**(見下條),不准 agent 對照本批比例校準。

6. 【對照組定義:推翻現行 EV31,改成同站位配對 + 兩檔硬度】這是我實測後對已 commit 程式碼的直接反對。`ev57_station_sample.py`(舊 ev31_resample 已刪) 現行對照 = 前 120 日漲 ≥25% 且前瞻最大 <20%。我在乾淨還原價上量:站位錨定下**正例只有 30.5% 滿足 prior120 ≥ +25%(中位僅 +3.8%)**,而現行對照池 100% 滿足、**中位 +43.1%**。兩組在前期動能上系統性差一大截,蒸餾必定把動能這個混淆因子學成判別力。改為:負例只需「同站位、同可執行母體、前瞻最大未達門檻」,配對鍵 =(站位 × 成交值截面十分位 × 前 120 日動能截面十分位),PIT 產業為優先軟鍵,逐級放寬並記錄放寬層級(我量到細格每格未漲候選中位 9 檔、p10 僅 3 檔,所以放寬階梯是必需的,不是選配)。負例再分兩檔硬度:`near_miss`(前瞻最高 25~50%)與 `quiet`(<15%),各約半數——`quiet` 在配平動能後即扮演設計 1 的隨機基準臂,故不另開第三臂。

7. 【九格最低檢索矩陣 G1-G9 + hit/miss/blocked/n_a 逐格留痕】舊年代最大的風險不是「沒有消息」,是「有消息但查不到卻被記成沒有消息」——那會讓哲學學到一條假規律「年代越早、暴漲越是純籌碼現象」,而那是搜尋引擎的性質不是市場的性質。取設計 4 的整套並收緊:只有 G1 該區間零非例行重訊 + G3 當年度與前一年度年報皆無對應敘述 + G5/G6/G7/G8 皆為 `miss` 而非 `blocked` + T1 層零 `blocked`,才准宣告「真的查無」;任一條不滿足一律記 `undetermined`。`retrievability_score` 0-3,蒸餾時「查無消息暴漲佔比」的分母只准用 ≥2 的樣本。年報(G3)是舊年代最被低估的金礦:有明確發布日、會回顧當年訂單客戶擴產、且永遠在 MOPS 上不會 404。

8. 【身分解析 identity_card + 年代語彙表 era_brief(批次共用只採一次)】設計 4 獨有、其餘四家全漏的兩個舊年代坑:(a) 用 2026 年的公司名搜 2010 年的新聞,結果是整片「查無」——先查站位當時的公司全名、英文名、是否更名換代號;(b) 2010 年沒有「AI 伺服器」只有「雲端運算」,用今天的詞搜舊年代必然空手——每個年代批開工先建當年語彙表。兩者皆存檔複用,符合「共用的觀測只採一次」。**修掉設計 4 的一個洩漏**:identity_card 在階段 A 不得含「站位之後是否下市/合併/被收購」,那是結果資訊,移到階段 B。

9. 【效率對稱:選『下限』不選『上限』】設計 1 要對搜尋次數設上限(tier A/B ≤12 次)以防努力洩漏,設計 4 要設下限(九格必跑)。我選下限、明確拒絕上限:那些次數沒有出處(違反「說不出量測來源就是魔術數字」),且在稀薄年代直接毀掉樣本。對稱性改由**結構**保證——兩組階段 A 提示詞逐字相同、批次混編使 agent 根本無從判斷該對誰加碼、`query_log` 含未命中查詢供稽核、蒸餾端另有一張「搜尋投入 vs 結果」的努力洩漏稽核表。

10. 【封閉詞彙 14 格 + 開放槽並存,且統計表由程式算】封閉詞彙(題材原型/價值鏈位置/題材階段/卡位證據強度/題材營收佔比/定價狀態/兌現時程/驅動持續性/當期數字方向/市場狀態/個股相對市場/證據等級/逼近觸發/題材級可觸及性)讓每一格可跨樣本製列聯表算 lift;`mechanism_tag` 開放自由文字由蒸餾端由下而上聚類(設計 3 的正確顧慮:預先發明的七類無從被證據推翻);`schema_gap` 為逃生口。配套鐵律:**蒸餾器禁止自己算數字**,所有比率一律引程式算好的表號——現行哲學的「6-6.5 成」「12.5-37.5%」正是 LLM 跨 200 份文件目測計數的產物(我實測流動性十分位命中率是 11.3% / 5.5~7.3% 的平坦曲線,那個 12.5-37.5% 區間根本不是分層估計,是批間極差)。

11. 【peer_set + 過度解釋檢驗 + 選股命中率】現行歸因只看被指定的那一檔,完全沒有量到標記 Agent 最貴的錯誤:「題材對了、選錯股」。加三件互補的欄位:`peers`(附一起被點名的來源與日期)、`story_also_fits`(把我的讀法原封套到同儕身上是否同樣選中他們——誠實答『是』即代表這套敘事零判別力)、`within_theme_rank`。peer 的前瞻報酬由量化引擎回填,蒸餾端才第一次量得出「找題材」與「同題材選名」各自貢獻多少。

12. 【期別保留組(era holdout)寫進蒸餾流程】蒸餾器先只讀蒸餾期別寫出 draft(檔案 mtime 可稽核),再讀保留期別做評分,**只准把規則標為 replicated / holdout_failed / untestable,嚴禁改寫或新增**,並輸出 `no_revision_declaration`。這是唯一能在蒸餾這一層檢驗跨 regime 可移植性的機制——否則多 regime 樣本只是給過擬合更多素材。搭配「保留組只能用一次」的紀律。

13. 【跨年代不變式檢定取代『多數觀察即通則』】每一道判別必須報 `era_support` / `era_counter` / `era_sparse` 與 `stability_verdict`:≥3 個期別有支持且無期別出現系統性反例才准寫成通則(INVARIANT);只在特定總經環境成立者降級為 REGIME_CONDITIONAL 並寫明適用與失效條件;疑似當年制度產物(漲跌幅上限 7%→10%、當沖規則)一律逐出判別、另列 `era_artifacts`。這是把樣本期前移的最大增量兌現成規則。

14. 【哲學章節結構 = 標記 Agent 輸出表單欄位】蒸餾產物逐節對應 theme / signal_type / event / evidence / invalidation / conviction / code-name,每節開頭必須寫「這一節怎麼幫標記 Agent 填哪一格」;`checklist` 每一步必須指回某條規則 id,指不回去的步驟即刪。哲學從十道判別的散文變成標記表單的填寫指南。

15. 【slow_burn 標籤:把策略層落差交給使用者裁決而不是默默選邊】我實測:站位後 2-6 個月最高 ≥80% 的樣本中,**26.2% 在站位後 30 個交易日內最高漲幅還不到 +10%**,而現役出場規格 time_days=30。每個樣本另記 fwd63 與 `slow_burn` 旗標,蒸餾被硬性要求分層報告並明寫「這一類即使判對,現行出場規格也吃不到」。我不替使用者決定要改標記問句、放寬時間停損、還是承認標記與收割是兩件事。

16. 【年代試跑先於全量,及格線先寫】按年代分批(E1..E6),每個年代先跑 1 批,及格線:該批 6 檔中至少 4 檔的 `retrievability_score ≥ 2`。不及格時只有兩個合法動作——縮減該層配額並在哲學裡明寫該 regime 證據較薄,或整層剔除並明說 regime 覆蓋損失;**不准默默照抽然後產出一份看起來很完整的哲學**。批次規模由 8 降為 6(2 對配對 + 2 檔未配對,使正負比例在 2:4 / 3:3 / 4:2 間浮動,避免 agent 從 50/50 反推),因為新增了兩站位、九格矩陣、identity_card、peers 與盲判,單檔工作量約為現行的 2 倍。

## 自陳未解風險

- **盲化擋不住兩個洞,而我只補了一個。** (a) 模型的內在記憶:對知名個股與大型股,agent 很可能本來就知道後來發生什麼,`prior_memory` 自陳無法驗證;緩解只能靠抽樣偏向中小型低知名度標的、並把 `prior_memory=true` 的樣本另外分層看 AUC。(b) 搜尋過程本身:搜尋引擎給的是今天的索引,一則舊新聞旁邊常掛著後來的回顧。檔案寫入順序只保證「寫下之前沒有主動去查」,不保證「沒有看到」。`leakage_log` 把它變成可觀測,但可觀測不等於可扣除——所以盲判 AUC 必須當**上界**用,不能當估計值。
- **這個設計會產出殺死自己的證據,而我沒有 Plan B。** 若 T5 的 AUC 信賴區間涵蓋 0.5,結論就是「質化標記層沒有邊際判別力、應該廢除」。這是我認為機率不低的單一結果(對照組人手一個好故事,前一版自己的報告就已經寫出來了)。必須在發射前就接受這個可能——否則跑到一半看到數字難看時,最大的誘惑是回頭改協定,而那正是所有回測作弊的起點。這個設計只保證能**便宜且早地**發現它(年代試跑就看得出苗頭),不保證能解決它。
- **成本沒有實測支撐。** 兩站位、九格矩陣、identity_card、peers、盲判、雙份輸出——單檔工作量我估是現行的約 2 倍,但那是估計不是量測。批次由 8 降為 6 只是部分抵銷。若總預算不變,樣本數會被砍到不足以支撐我要求的分層(regime × 覆蓋 × 流動性帶),而樣本數正是新樣本期最需要的東西。發射前必須先跑一個年代批實測單 agent token 再核定全量,不能用直覺定預算。
- **分層宣稱與樣本量可能對不上。** 我要求哲學按期別 × 覆蓋 × 流動性帶分層報告,但若總樣本只有 120-150 對,切成 6 個期別再切覆蓋,每格只有十幾對——那個粒度的命中率估計誤差極大,很容易蒸餾出「某期別特別有效」的雜訊結論。合理的收斂是把哲學的分層宣稱限制在期別一維,但我沒有把這個限制寫死進提示詞,而是靠信賴區間鐵律被動擋——那可能導致蒸餾器把大半判別都推進 `undecided`,產出一份「什麼都沒定案」的哲學。
- **排除 `NOT_RETRIEVABLE` 樣本會產生新的選擇偏誤。** 可檢索性與「當年受關注程度」正相關,而受關注程度本身可能與暴漲機制相關——校正後的分母系統性偏向「當年就有能見度」的樣本,哲學可能低估「完全冷門股」這一整類機制。這個偏誤方向已知,我要求在 `honest_boundary` 揭露,但**沒有解法**。
- **去識別化的代價我沒有量。** 蒸餾器拿到匿名卡片後:無法交叉驗證、無法察覺兩張卡其實講的是同一個事件(重複計數風險)、無法從具體案例看出抽象描述漏掉的細節;而某些機制的判別力本來就綁在產業結構上(半導體上游的「瓶頸」與紡織上游的「瓶頸」不是同一回事),封閉詞彙壓成同一格可能系統性遺失訊號——**而這個損失在事後看不出來**(你只會看到 lift 偏低,不知道是市場沒訊號還是詞彙太粗)。要量它,得跑一次「有名字版蒸餾」對照,那是額外一次蒸餾成本。
- **封閉詞彙的 14 格是我從舊哲學逆向拆出來的,本身就是一個先驗。** 若真正的判別力落在這 14 格之外,只靠 `novel_features` 與 `schema_gap` 可能撈不上來——而它們又因為要事後正規化才能製表,第一輪必然只能標成「待表證」。等於第一輪蒸餾對「詞彙外的新發現」幾乎沒有產出能力。應在小樣本階段先跑一批、人工檢查 `schema_gap` 內容分布再決定是否擴充詞彙,這一步我列出來了但沒有寫進流程。
- **`ex_ante` 凍結後補不了洞。** 若階段 A 在某檔搜得不夠,那個洞會永久帶進機制卡並被記成「當時查無」。在稀薄年代這會系統性偏向 `no_pre_station_news = true`,讓哲學高估「查無消息暴漲」的占比、進而過度擴大棄權區。`retrievability_score` 分層只能標示這個風險,不能修正它。
- **`peers` 的 recall 無法驗證,且可能被搜尋曝光度污染。** agent 列出的同儕是它自己想得到、且今天搜得到的那幾檔;真正的同題材受惠股可能整片漏掉。因此 T8 量到的是「在 agent 想得到的候選集合內的取捨能力」,不是全市場選股能力。由程式用 PIT 產業 + 市值分位指定 peers 會更客觀,但會削弱「同題材」的語意精度——這個取捨我沒有解掉。
- **九格的「窮盡」是 agent 自己填的,沒有第三方驗證。** 一個偷懶的 agent 可以把 `blocked` 填成 `miss` 來取得宣告 `NO_NEWS_EXISTS` 的資格,反而讓假的「真的沒消息」看起來有憑有據。緩解需要抽樣重跑(隨機抽 10% 由另一批 agent 盲跑同一份矩陣比對),我列出來了但沒有寫進流程。
- **保留期別的「不准回頭改」只靠檔案 mtime 與一句自我宣告**,在單一 agent 內沒有真正的物理隔離。要做硬的得拆成兩個 agent(A 寫規則、B 只做保留組評分),但 B 仍需要規則全文才能評分,隔離收益有限而編排成本翻倍。這確實是本設計最軟的一環。
- **`{sample_period_end}` 這個時間上限對搜尋工具是不可強制的。** agent 可以照做,但沒有機制能阻止一次 WebSearch 回傳 2024 年的頁面。日期審計只能事後抽查。
- **下游前提有破口,而它會讓整個重新蒸餾的收益打折。** 我實測確認:`ex_right_dividend` 的 TWSE 在 **2023-09 至 2024-06 整整 10 個月零筆**(2023-08 有 97 筆、2024-07 才恢復 169 筆),且 `data/` raw 封存本身就缺檔——需要**重爬**,不是重建就能解決。那個窗裡除權息事件沒有還原因子,還原價會帶機械跳空,而它正好落在 live 策略的 refit 窗(2023-07~2026-07)內,與 EV30 抓到的幽靈暴漲是同一個機制。也就是說:即使蒸餾樣本重做得再乾淨,**用來驗證新哲學的 2022-2026 回測仍站在一個有洞的地基上**。這不在我的任務範圍,但它必須先補。
- **對照組定義的改動要求動已 commit 的程式碼。** `ev31_resample.py` 現行的 `CTRL_PRIOR_MIN = 0.25` 與 `_match_controls` 的配對鍵(月 × 產業 × 流動性三分位)都必須改成我提出的(站位 × 成交值十分位 × 前期動能十分位,產業為軟鍵),否則歸因提示詞會拿到與其假設不符的樣本。我只交付提示詞,沒有改那支程式——這是一個明確的、必須有人接手的相依。
   **【2026-07-27 已接手】** 該相依已實作為 `ev57_station_sample.py`(站位錨定 + 配對動能十分位),舊 `ev31_resample.py` 已刪除。修後實測:正例 prior120 中位 +9.0% vs 負例 +4.8%(原為 −7.3% vs +33.7%,差 41 個百分點),動能十分位中位兩邊皆 6。
- **站位錨定讓每個樣本變難,可能讓歸因品質整體下降。** 事件錨定的 t0 站在起漲日,消息密度天然高、好寫;站位錨定的 `d0` 可能落在一段沉悶期的中間,研究員搜半天只搜到零星材料,`不可考` 比例會顯著上升。這在方法上是對的(那才是標記 Agent 的真實處境),但會讓報告看起來「產出很少」——若以報告豐富度判斷成敗,這個設計會被誤判為失敗。
- **配對控制掉的東西,可能正是真正做功的東西。** 我把站位、流動性、前期動能配平以消除混淆;但若大漲的真實驅動有很大一塊本來就是產業輪動與動能,配對等於把訊號一起減掉,剩下的殘差可能薄到蒸餾不出東西。這是配對設計的固有代價,我沒有量。可行的緩解是額外保留一小批**未配對**的隨機負例當第三臂做對照,但那會再推高成本。
- **`p_up80` 的絕對水準幾乎一定沒有校準。** LLM 系統性樂觀或錨在中段值,AUC(排序能力)可用,但機率本身不可直接餵給下游當先驗;若下游想用機率加權部位,必須先做等分位重新校準——這一步我沒有設計。
